§ 1. The Loop

ReAct names a simple control pattern: the model alternates between deciding what it believes, choosing an external action, and reading the result of that action. A thought is not an answer; it is the controller’s current state. An action may be a search, a database query, a calculation, or a call to another service. The observation is then appended to the trace and becomes evidence for the next thought. This loop lets a language model ground its next token choices in measurements from the world rather than in memory alone. The intelligence is distributed across the model, the tools, and the trace.

§ 4. Where Loops Fail

Agent loops create their own failure mode: every thought, action, observation, error message, and retry is added to the context. Early iterations look cheap, but tool outputs are uneven and summaries often preserve the wrong details. As the trace length grows, retrieval inside the prompt becomes noisy. The model may still generate fluent next actions while losing the causal state that made those actions valid.

§ 5. The Loop, in Code

def react(question, model, tools, max_steps=8):
    trace = [{"role": "user", "content": question}]

    for step in range(max_steps):
        prompt = render_prompt(trace)
        thought = model.complete(
            prompt,
            stop=["ACTION:"]
        ).strip()

        trace.append({
            "role": "assistant",
            "kind": "thought",
            "content": thought
        })

        action = parse_action(
            model.complete(prompt + thought)
        )

        if action.name == "answer":
            return action.args["text"]

        result = tools[action.name](**action.args)

        trace.append({
            "role": "tool",
            "kind": "observation",
            "name": action.name,
            "content": result
        })

    return summarize_failure(trace)
THINK: ask the model to produce the next internal state from the accumulated trace.
ACT: parse a bounded, typed operation rather than free-form prose.
OBSERVE: append the tool result so the next thought is conditioned on evidence.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6. Ending

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
