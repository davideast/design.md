§ 1. The Loop

The ReAct loop is a controller.

ReAct names a simple discipline for making a language model act in the world: alternate reasoning with grounded action. The model first writes down what it believes it should do next, then calls a tool, receives the tool’s output, and folds that observation back into the next decision. The loop is not just prompt formatting. It is a control structure that lets a stochastic text generator maintain contact with external state: search results, files, APIs, simulators, databases, and user feedback. Progress comes from repeated correction. Each observation narrows the gap between the model’s internal story and the world.

§ 2. A Worked Trace

A trace is the agent’s audit log.

Query: “What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?”
01
THOUGHT Identify the keynote date before fetching market data.
ACTION search_web("Jensen Huang 2024 keynote date")
OBSERVATION NVIDIA GTC keynote occurred March 18, 2024.
02
THOUGHT The day after is March 19, 2024; verify it was a trading day.
ACTION calendar.check_market_day("2024-03-19")
OBSERVATION NASDAQ open; regular session trading day.
03
THOUGHT Retrieve official historical price for NVDA on that date.
ACTION market_data.get_ohlc("NVDA","2024-03-19")
OBSERVATION Close: 89.398 USD, split-adjusted.
04
THOUGHT Check whether the user expects pre- or post-split notation.
ACTION market_data.get_corporate_actions("NVDA","2024")
OBSERVATION 10-for-1 split effective June 10, 2024.
05
THOUGHT Convert adjusted close to contemporaneous pre-split price if needed.
ACTION calculator.multiply(89.398, 10)
OBSERVATION 893.98 USD.
06
THOUGHT Answer with date, source convention, and caveat.
ACTION final_answer()
OBSERVATION NVDA closed at $893.98 then, or $89.40 split-adjusted.
Resolve ambiguous event language into a concrete date.
The calendar tool prevents weekend and holiday errors.
The agent asks for data rather than inventing a price.
Corporate actions change how historical prices are displayed.
A small deterministic calculation is delegated to a tool.
The final response preserves provenance and convention.

§ 4. Where Loops Fail

Failure often looks like too much history.

Context-window exhaustion is the quiet failure mode of agent loops. Every thought, tool call, observation, retry, and diagnostic note becomes part of the next prompt unless the system compresses or discards it. The model may still have nominal room for tokens, but effective attention degrades: early constraints fade, irrelevant observations compete with decisive ones, and the agent starts re-solving subproblems it already solved.

§ 5. The Loop, in Code

A minimal ReAct controller.

def react(model, tools, question, max_steps=8):
    trace = []
    state = {"question": question}

    for step in range(max_steps):
        prompt = render_prompt(state, trace)

        thought = model.complete(
            prompt,
            stop=["ACTION:"]
        )
        trace.append(("THOUGHT", thought))

        action = model.complete(
            prompt + thought + "\nACTION:",
            stop=["OBSERVATION:"]
        )
        name, args = parse_action(action)
        trace.append(("ACTION", action))

        if name == "final":
            return args["answer"], trace

        result = tools[name](**args)
        observation = summarize(result)

        trace.append(("OBSERVATION", observation))
        state = update_state(state, observation)

    return "No answer within budget.", trace
THINK: the model proposes the next move in language, making intent inspectable before side effects occur.
ACT: parsing constrains free text into a typed tool invocation with arguments.
OBSERVE: tool output is summarized and returned to the prompt as new evidence.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6. Ending

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
