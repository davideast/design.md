§ 1. The Loop

The ReAct loop is the smallest interesting agent: a controller that interleaves private reasoning with tool-mediated action. At each turn the model emits a thought — a plain-language inference about the current state — then an action — a structured call into the world — and receives an observation back.

What makes this architecture and not mere prompting is the closure: the observation is folded into the next thought. The model never acts from a frozen plan; it re-decides at every step, conditioned on what the world actually returned.

§ 2. A Worked Trace
Query "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
01 Thought I need to find the date of Jensen Huang's 2024 keynote first, then look up NVDA's closing price the following trading day.
02 Action search("Jensen Huang 2024 keynote date")
03 Observation NVIDIA GTC 2024 keynote — March 18, 2024, San Jose.
04 Thought The keynote was March 18. The next trading day is March 19. I should fetch NVDA's close on that date.
05 Action finance.close("NVDA", "2024-03-19")
06 Observation NVDA closed at $950.02 on 2024-03-19, up 2.05%.
07 Thought I have both components. The query is answered; emit final.
08 Action finish("NVDA closed at $950.02 on March 19, 2024.")
Decomposition before retrieval — the model plans its dependencies.
A single, well-typed tool call; no prose to the environment.
The world returns a fact, not a verdict.
Trading-day awareness — reasoning about calendar structure.
Reuses the tool interface; no new capability needed.
A number with provenance; the model can now commit.
Self-assessment: the loop knows when to stop.
A terminal action — control returns to the caller.

§ 4. Where Loops Fail

Agents do not usually fail because the model cannot, in principle, solve the task. They fail because each iteration appends a thought, an action, and an observation to the context — and the context grows monotonically.

Around the inflection point, effective attention collapses faster than the model's nominal capability. The loop is still running; the model is no longer reading its own history.

§ 5. The Loop, in Code
react_loop.py · minimal ReAct
# minimal ReAct loop — three steps, one cycle
def react(query, tools, model, max_iter=10):
    ctx = [{"role": "user", "content": query}]
    for i in range(max_iter):
        # ── THINK ──────────────────────────────
        out = model.complete(ctx, stop=["Action:"])
        thought = out.text.strip()
        ctx.append({"role": "assistant", "content": thought})

        if "Final:" in thought:
            return thought.split("Final:")[1].strip()

        # ── ACT ───────────────────────────────
        action = parse_action(thought)        # name + args
        result = tools[action.name](**action.args)

        # ── OBSERVE ───────────────────────────
        obs = f"Observation: {result}"
        ctx.append({"role": "user", "content": obs})

    raise RuntimeError("loop exhausted")
→ Think
A single completion call, stopped at the action boundary. The thought is appended verbatim — never silently transformed.
→ Act
Parsing is structural, not semantic. The model emits a typed call; the harness dispatches it. No free-form execution.
→ Observe
The result re-enters as a user turn. The model cannot tell its own observations from the world's replies — that symmetry is the point.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6 · Ending

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
