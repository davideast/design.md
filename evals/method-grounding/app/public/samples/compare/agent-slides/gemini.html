§ I
§ 1. The Loop

The ReAct (Reasoning and Acting) loop represents a fundamental shift from static prompting to dynamic agency. In this architecture, the language model is not merely a generator of text but a controller in a closed-loop system. It first generates a THOUGHT, articulating its internal reasoning process. This leads to an ACTION—a call to an external tool or environment. The result of this action, the OBSERVATION, is fed back into the model's context. This feedback loop allows the agent to update its internal state, correct previous errors, and refine its strategy until a final goal is achieved.

Fig. 1. The basic loop. Note that OBSERVE returns to THINK; this is what makes the architecture a controller, not a pipeline.

§ II
§ 2. A Worked Trace

QUERY: "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"

Thought I need to identify the exact date of Jensen Huang's 2024 GTC keynote. Initial Planning
Action search("Jensen Huang GTC 2024 keynote date") Tool Invocation
Observe "The keynote took place on Monday, March 18, 2024." External Input
Thought The day after March 18 is March 19, 2024. I will look up NVDA's price for that date. State Update
Action search("NVDA stock closing price March 19 2024") Refined Query
Observe "NVDA closed at $893.98 on March 19, 2024, up 1.07%." Data Retrieval
Thought I have the required information to answer the user query. Termination

The trace serves as a verifiable log of the agent's logic. By examining the intermediate THOUGHT steps, we can diagnose whether a failure occurred in retrieval, logic, or tool execution.

§ IV
§ 4. Where Loops Fail

Even the most robust agent architectures encounter a structural limit: the context window. As the loop iterates, the trace of previous thoughts, actions, and observations accumulates. This growth is typically linear until the model begins to lose coherence or 'forget' early instructions. When the context exceeds the model’s effective attention span, the reasoning quality degrades sharply. This 'lost in the middle' phenomenon means long-running agents require aggressive pruning or summarization strategies.

§ V
§ 5. The Loop, in Code
def run_agent(prompt: str, max_iters: int = 10): context = [{"role": "system", "content": SYSTEM_PROMPT}, {"role": "user", "content": prompt}] for i in range(max_iters): # 1. THINK response = llm.generate(context, stop=["Observation:"]) context.append({"role": "assistant", "content": response}) # 2. ACT action = parse_action(response) if not action: return response # Final answer reached # 3. OBSERVE result = execute_tool(action.name, action.args) observation = f"Observation: {result}" context.append({"role": "user", "content": observation}) return "Error: Max iterations exceeded."
The THINK step: The model generates its internal monologue and chosen tool call.
The ACT step: Parsing the structured output to invoke local python functions.
The OBSERVE step: Tool output is injected back into the prompt for the next turn.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.
