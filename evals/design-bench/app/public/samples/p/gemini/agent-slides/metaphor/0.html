§ 1. The Loop

The agentic paradigm shifts language models from static predictors to active participants in an environment. In a ReAct (Reason + Act) loop, the model does not attempt to solve a complex query in a single forward pass. Instead, it decomposes the problem into a sequence of interleaving steps. It generates a thought, selects an external tool, and receives an observation. Crucially, this observation is fed back into the model’s context. This feedback loop allows the model to correct its own errors, update its internal state based on real-world data, and navigate towards a solution through iterative refinement.

§ 4. Where Loops Fail

Context windows are the finite resource of the agent loop. As an agent iterates, every thought, action, and observation is appended to its history. This linear growth eventually hits a point of diminishing returns. As the context fills, the model’s attention mechanism begins to blur, often losing the original task instructions or hallucinating the state of the environment. The result is an inflection point where cost increases while performance collapses, leading to infinite loops or nonsensical tool calls.

§ 5. The Loop, in Code
def run_agent(task, tools, llm): context = f"Task: {task}\n" for i in range(MAX_ITERATIONS): # 1. THINK step thought = llm.generate(context + "Thought:") # 2. ACT step action = llm.generate(context + thought + "Action:") if "FINISH" in action: return parse_final(action) # 3. OBSERVE step observation = tools.execute(action) # Closing the loop context += f"T: {thought} A: {action} O: {observation}" return "Timeout: Max iterations reached."
[ THINK ]
Internalize current state and determine next logical pivot.
[ ACT ]
Translate intent into a structured tool call or environment signal.
[ OBSERVE ]
Grounded environmental feedback ingested as new context.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
