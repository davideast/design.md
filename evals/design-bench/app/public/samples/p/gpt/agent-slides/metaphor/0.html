Agent Architecture

On loops, traces, and the structures by which language models act.

A. Ramanathan · Systems Group

14 October 2026

§ 1. The Loop

ReAct names a simple control loop for language-model agents. The model first thinks: it states what it knows, what it needs, and what action would reduce uncertainty. It then acts by calling a tool, searching, calculating, reading a file, or issuing some other external command. The environment returns an observation. That observation is appended to the trace and becomes part of the next thought. The agent is therefore not merely generating a chain of text; it is repeatedly choosing interventions, reading their consequences, and updating its local state until it can answer or stop.

§ 4. Where Loops Fail

Context-window exhaustion is the ordinary failure mode of long-running agents. Each iteration appends thoughts, tool calls, observations, errors, retries, and partial products. Early growth looks manageable because the trace is short and relevant. Later, the agent spends tokens restating its own history, searching over stale evidence, and carrying obsolete branches. The loop still turns, but its control signal degrades: more context is present, while less of it is effectively attended.

Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.

§ 5. The Loop, in Code

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes. 

def react(question, model, tools, max_iter=8):
    trace = [{"role": "user", "content": question}]

    for i in range(max_iter):
        thought = model.complete(
            trace + [{"role": "system",
                      "content": "Think, then choose an action."}]
        )
        trace.append({"role": "thought",
                      "content": thought})

        action = parse_action(thought)
        if action.name == "finish":
            return action.args["answer"], trace

        if action.name not in tools:
            observation = f"unknown tool: {action.name}"
        else:
            observation = tools[action.name](**action.args)

        trace.append({"role": "observation",
                      "content": observation})

    final = model.complete(
        trace + [{"role": "system",
                  "content": "Answer from the trace."}]
    )
    return final, trace

THINK

The model writes an explicit intermediate state into the trace.

ACT

The thought is parsed into a bounded tool invocation.

OBSERVE

The environment's result is appended before the next turn.

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
