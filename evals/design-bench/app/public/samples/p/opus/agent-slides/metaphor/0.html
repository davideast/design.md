§ 1. The Loop

The ReAct loop is the smallest complete agent. The model thinks — it writes a short reasoning step in plain language. It then acts — it issues a single tool call or query into the world. The world responds, and the model observes that response. Crucially, the observation does not end the process: it returns to thinking, where the model decides what to do next in light of what it just learned. Reasoning and action interleave, one step at a time, until the model judges the task complete. The loop is a controller because the output of each turn shapes the input to the next.

Fig. 1. The basic loop. Note that OBSERVE returns to THINK; this is what makes the architecture a controller, not a pipeline.
§ 2. A Worked Trace
Query: "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
THOUGHT   I need the date of Jensen Huang's 2024 keynote first. ACTION    search("Jensen Huang 2024 keynote date")
Decompose: the query hides a dependency — a date must precede the price lookup.
OBSERVE   GTC 2024 keynote: 18 March 2024.
Observation feeds the next thought, not a final answer.
THOUGHT   "The day after" = 19 March 2024. Get NVDA close for that date. ACTION    price("NVDA", date="2024-03-19", field="close")
Date arithmetic is externalized as reasoning, not assumed.
OBSERVE   2024-03-19 was a trading day. Close: 893.98 (split-adjusted: 89.40).
Tool returns ambiguity — two figures, pre- and post-split.
THOUGHT   Ambiguous. The query implies the headline price as quoted in March 2024. ACTION    verify("NVDA split 2024 date")
The loop catches the ambiguity rather than guessing.
OBSERVE   10-for-1 split effective 10 June 2024 — after the date in question.
The pre-split figure is the as-quoted close.
THOUGHT   Resolved. The as-quoted close on 2024-03-19 was 893.98. ACTION    finish("$893.98")
Termination: the model judges the task complete.
§ 3. Four Architectures
REACT
The bare loop: reason, act, observe, repeat.
REFLEXION
A MEMORY node stores reflections that re-enter THINK.
PLAN-AND-EXECUTE
A PLAN node feeds the cycle, fixing the steps in advance.
TREE-OF-THOUGHTS
THINK branches into two children; the best is selected before ACT.
§ 4. Where Loops Fail

Each turn appends its thought, action, and observation to the context. Early iterations add little; later ones carry the full accumulated trace. The token count does not grow linearly — it inflects upward, because each observation must now be read against everything before it. Past a threshold, the prompt outruns the model's effective attention, and the loop degrades: it forgets its plan, repeats actions, and stalls. The failure is structural, not a deficit of the model.

● Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.
§ 5. The Loop, in Code 
def react(query, tools, model, max_iter=25):
    trace = [f"Query: {query}"]
    for _ in range(max_iter):
        prompt = "\n".join(trace)

        thought = model.complete(
            prompt + "\nThought:")
        trace.append(f"Thought: {thought}")

        action = model.complete(
            prompt + "\nAction:")
        name, arg = parse(action)
        trace.append(f"Action: {name}({arg})")

        if name == "finish":
            return arg

        result = tools[name](arg)
        trace.append(
            f"Observation: {result}")

    raise LoopExhausted(trace)
THINK
The model writes a thought before any action. Reasoning is forced into the trace.
ACT
Exactly one tool call per turn, parsed from the model's output and dispatched.
OBSERVE
The result is appended and re-enters the prompt — the line that closes the loop.
The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.
§ 6. Ending
The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
