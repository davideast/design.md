§ 1. The Loop

The Loop

An agent is not a model. An agent is a loop wrapped around a model. The model thinks; the loop acts and observes. Each cycle refines the agent's understanding of the world. The architecture is minimal: receive an observation, produce a thought, take an action, observe the result, and repeat. Every modern agent framework — from ReAct to Reflexion to Plan-and-Execute — is a variation on this single structure. The loop is the invariant.

§ 2. A Worked Trace

A Worked Trace

Query: "What was NVDA's closing price last Friday?"

Thought 1 I need to find NVDA's closing price from last Friday. I should use a financial data tool.
Action 1 search("NVDA stock price last Friday")
Observation 1 Error: search tool returned rate-limit exceeded. Retry in 5s.
Thought 2 Rate-limited. I'll switch to the financial API instead.
Action 2 finance.get_price(ticker="NVDA", date="2026-10-09")
Observation 2 {"ticker": "NVDA", "close": 148.36, "date": "2026-10-09"}
Thought 3 I have the closing price. I can now respond to the user.
Action 3 respond("NVDA closed at $148.36 on Friday, October 9.")

↗ First tool selection — greedy, picks search over API

↗ Error recovery: the loop self-corrects without external prompt

↗ Termination condition — agent judges sufficiency of evidence

§ 4. Where Loops Fail

Where Loops Fail

Loops degrade. Each iteration consumes tokens that crowd the context window, diluting the signal that earlier observations carried. Past a threshold — usually 8–12 iterations for current models — the agent begins to hallucinate actions it already took, re-attempt failed strategies, or lose track of the original goal entirely. The failure mode is not a crash; it is a slow drift into incoherence.

§ 5. The Loop, in Code

The Loop, in Code

def agent_loop(query, tools, model, max_iter=10):
    trace = []
    observation = query

    for i in range(max_iter):
        # THINK
        thought = model.generate(
            prompt=format_prompt(trace, observation)
        )

        # ACT
        action = parse_action(thought)
        if action.type == "respond":
            return action.payload

        result = tools.execute(action)

        # OBSERVE
        observation = result
        trace.append({
            "thought": thought,
            "action": action,
            "observation": observation,
        })

    raise LoopExhausted(trace)

← The prompt is rebuilt each cycle. The trace is the memory; there is no external state.

← Termination: the model itself decides when to stop. respond breaks the loop.

← A hard ceiling. Without it the loop drifts — cf. § 4.

Twenty-five lines. The rest — retrieval, planning, reflection — is furniture arranged around this room.

§ 6. Ending

The architecture is the loop.

What varies is the memory passed to the next iteration, the policy for selecting actions, and the criteria for stopping. Everything else is commentary.
