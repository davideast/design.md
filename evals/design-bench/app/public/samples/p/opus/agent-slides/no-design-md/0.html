§ 1. The Loop

The ReAct loop is the smallest complete agent. The model first thinks: it states, in natural language, what it intends to do and why. It then acts, emitting a single tool call or final answer. The environment returns an observation, which the model reads before thinking again. Reasoning and action alternate in lockstep — each observation conditions the next thought. Because the loop has no fixed length and decides at every turn whether to continue, it behaves as a controller responding to feedback rather than a script executing fixed stages. The trace it leaves is its reasoning, made legible.

THINK
↓
ACT
↓
OBSERVE
⟲ returns to THINK

Fig. 1. The basic loop. Note that OBSERVE returns to THINK; this is what makes the architecture a controller, not a pipeline.

§ 2. A Worked Trace
Query: "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
THOUGHT I need the date of Jensen Huang's 2024 keynote first.
Decomposes the query before any tool fires.
ACTION search("Jensen Huang 2024 keynote date")
A single, scoped tool call — not a batch.
OBSERVATION GTC 2024 keynote held 18 March 2024.
Result re-enters the context as plain text.
THOUGHT "Day after" means the trading day of 19 March 2024.
Resolves the relative reference explicitly.
ACTION quote("NVDA", date="2024-03-19", field="close")
Now over-specified to avoid ambiguity.
OBSERVATION NVDA close 2024-03-19 = 893.98 (pre-split).
Note the caveat the model must reconcile.
THOUGHT Value is pre-split; report as-is with that caveat.
Decides it has enough to stop looping.
ACTION finish("NVDA closed at $893.98 on 19 Mar 2024, pre-split.")
The terminating action ends the loop.

§ 4. Where Loops Fail

Every iteration appends its thought, action, and observation to the context. Nothing is freed by default, so the prompt grows monotonically — and observations, raw tool output, grow fastest of all. The curve is not linear: as the window fills, the model attends less reliably to its earliest instructions, and errors compound. The loop does not crash; it quietly degrades, looping past the point where it can still reason over its own history.

Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.

§ 5. The Loop, in Code
# minimal ReAct loop
def run(query, tools, model, max_steps=10):
    history = [system_prompt(tools)]
    history.append(f"Query: {query}")

    for step in range(max_steps):
        thought = model.complete(history)
        history.append(f"THOUGHT: {thought}")

        action = parse_action(thought)
        if action.name == "finish":
            return action.args["answer"]
        history.append(f"ACTION: {action}")

        result = tools[action.name](**action.args)
        observation = format_obs(result)
        history.append(f"OBSERVATION: {observation}")

    raise StepLimit("loop did not converge")
THINK The model writes a thought conditioned on the full history; it must reason in words before it is allowed to act.
ACT The thought is parsed into a single typed action — either a tool call or the terminating finish.
OBSERVE Tool output is formatted and appended, becoming context the next THINK must read.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6. Ending

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
