§ 1. The Loop

The ReAct loop is the simplest structure by which a language model can act in the world. At each turn the model produces a THOUGHT — a short reasoning step in natural language — and then commits to an ACTION, typically a call to a tool or search. The environment returns an OBSERVATION, and crucially that observation is fed back as input to the next thought. The model does not plan the whole trajectory in advance; it reasons one step at a time, conditioning each decision on what it has just seen. Reasoning and acting interleave until the task is resolved.

§ 2. A Worked Trace
Query: "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
THOUGHT I need the date of Jensen Huang's 2024 keynote first.
Decompose: the query hides a two-step lookup.
ACTION search("Jensen Huang 2024 keynote date")
Tool call, not an answer.
OBSERVATION GTC 2024 keynote — 18 March 2024.
Grounds the next thought.
THOUGHT The day after is 19 March 2024 — a Tuesday, market open.
Reasoning over the observation.
ACTION price("NVDA", "2024-03-19", "close")
Second tool call, now parameterized.
OBSERVATION NVDA close 2024-03-19 = 89.36 (split-adjusted).
Raw fact returned.
THOUGHT I have both pieces; I can answer directly.
Loop termination condition met.
ACTION finish("NVDA closed at 89.36 on 19 March 2024.")
Exit action ends the loop.

§ 4. Where Loops Fail

Every iteration appends its thought, action, and observation to the running context. The growth is not linear: observations accrete, and earlier reasoning is re-read at each step, so tokens rise and then inflect sharply upward. Long before the hard context limit, the model's effective attention degrades — it begins to ignore early instructions and lose the thread of its own plan. The loop does not crash; it quietly drifts.

Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.

§ 5. The Loop, in Code
# minimal ReAct controller
def react(query, tools, max_iter=10):
    history = [system_prompt(tools)]
    history.append(user(query))

    for step in range(max_iter):
        # THINK
        thought = llm(history, stop=["ACTION:"])
        history.append(thought)

        # ACT
        action = parse_action(llm(history))
        history.append(action)
        if action.name == "finish":
            return action.args["answer"]

        # OBSERVE
        result = tools[action.name](**action.args)
        obs = f"OBSERVATION: {result}"
        history.append(obs)

    return "max iterations reached"
THINKGenerate reasoning text, halting before the action token so thought is committed before acting.
ACTParse a structured tool call; finish is the sole exit, terminating the loop cleanly.
OBSERVEExecute the tool and append its result, closing the cycle back to the next THINK.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6. Ending

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
