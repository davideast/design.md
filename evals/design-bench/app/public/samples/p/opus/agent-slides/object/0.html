§ 1. THE LOOP

§ 1. The Loop

The ReAct loop is the simplest thing that deserves to be called an agent. The model is given a goal and then asked, repeatedly, to do three things in turn. First it thinks — it writes, in plain language, what it believes and what it intends to try next. Then it acts — it calls a tool, runs a query, takes a single concrete step in the world. Then it observes — it reads back whatever the world returned. And then, crucially, it thinks again. The observation does not end the process; it feeds the next thought. Reasoning and action alternate until the goal is met.

Fig. 1. The basic loop. Note that OBSERVE returns to THINK; this is what makes the architecture a controller, not a pipeline.

§ 2. A WORKED TRACE

§ 2. A Worked Trace

Query: "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
THOUGHT  I need the date of Jensen Huang's 2024 keynote first.
ACTION   search("Jensen Huang 2024 keynote date")
OBSERVE  GTC keynote held 18 March 2024.
The model decomposes; it cannot price what it cannot date.
THOUGHT  "Day after" means the next trading day, 19 March.
ACTION   calendar.next_trading_day("2024-03-18")
OBSERVE  2024-03-19 (Tuesday, market open).
Calendar reasoning is offloaded — a weekend would shift this.
THOUGHT  Now fetch NVDA's close on that date.
ACTION   prices.close("NVDA", "2024-03-19")
OBSERVE  $89.78 (split-adjusted close).
A second tool, parameterized by the first tool's output.
THOUGHT  I have a dated, source-backed figure. I can answer.
ACTION   finish("NVDA closed at $89.78 on 19 Mar 2024.")
Termination is itself an action — the loop must elect to stop.

§ 4. WHERE LOOPS FAIL

§ 4. Where Loops Fail

Each iteration appends to the context: the thought, the action, the observation, all of it kept so the model can reason over its own history. The cost is silent and compounding. Early iterations add little; later ones drag the full transcript along. The curve of tokens against iterations does not climb steadily — it inflects, bending upward as observations accumulate and re-enter the prompt. Long before the hard token limit, the effective limit arrives.

Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.

§ 5. THE LOOP, IN CODE

§ 5. The Loop, in Code

def react(goal, tools, llm, max_iters=20): history = [] for step in range(max_iters): thought = llm.think(goal, history) history.append(("THOUGHT", thought)) action = llm.decide_action(thought) if action.name == "finish": return action.answer result = tools[action.name]( **action.args ) observation = format_obs(result) history.append(("ACTION", action)) history.append(("OBSERVE", observation)) raise LoopExhausted( "no answer within max_iters" )
THINK. The model writes its reasoning over the goal and full history before committing to anything.
ACT. A single tool call is selected and executed; "finish" is the one action that exits the loop.
OBSERVE. The tool's return is formatted and appended, becoming input to the next THINK.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6. Ending
