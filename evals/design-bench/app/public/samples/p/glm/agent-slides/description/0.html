§ 1 — Foundations

The Loop.

ReAct names the simplest useful thing an agent can be: a loop in which a language model reasons about its situation, takes an action in the world, and reads back what changed. Reasoning produces a plan; action carries it out; observation reports the result. The cycle then repeats.

What makes this an architecture rather than a prompt is the closing edge — observation returning to thought. That single turn converts a pipeline into a controller, and is the reason the system can be said to act.

Fig. 1. The basic loop. Note that OBSERVE returns to THINK; this is what makes the architecture a controller, not a pipeline.

A Worked Trace.

Query — "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
01 Thought I need the date of Jensen Huang's 2024 keynote, then the trading day immediately after, then NVDA's close on that day.
02 Action search("Jensen Huang keynote 2024 date")
03 Observation "NVIDIA GTC 2024 keynote — March 18, 2024, San Jose." Monday.
04 Thought The next trading day after Monday March 18 is Tuesday March 19 — markets were open. Fetch NVDA close for 2024-03-19.
05 Action stock_close("NVDA", "2024-03-19")
06 Observation "NVDA closed at $919.13 on 2024-03-19, up 2.4% from the prior session."
07 Thought I have both ingredients. Compose the answer and stop.
08 Action finish("$919.13, the close on 19 March 2024, the trading day after Huang's GTC keynote.")
The first thought breaks the question into three concrete sub-goals before any tool is touched.
Each action names a specific tool and arguments — never a vague "look it up".
Observations are returned verbatim and become the substrate for the next thought.
The agent decides to stop. No external scheduler is required.
Trace terminates at step 08

§ 4 — Failure modes

Where Loops Fail.

Every iteration of an agent loop writes back into the same context window. Tokens accumulate: the query, the prior thoughts, the tool calls, the verbatim observations, the prompts the framework adds to keep things tidy. The history is the working memory of the system — and it grows monotonically with every step.

Eventually the history is longer than the model can attend to effectively. The agent begins to lose track of its own goal, to repeat actions, to forget what it has already established. The loop has not crashed. It has simply degraded past the point of useful work.

§ 5

The Loop, in Code.

Python · minimal ReAct 
01# minimal ReAct loop — the entire architecture, in 25 lines
02
03def react(query, tools, model, max_steps=20):
04    history = [{"role": "user", "content": query}]
05
06    for step in range(max_steps):
07        # THINK — let the model externalize its reasoning first
08        thought = model.complete(history + [{
09            "role": "system",
10            "content": "State your reasoning, then pick an action."
11        }])
12        history.append({"role": "assistant", "content": thought})
13
14        # ACT — parse & execute the chosen tool, if any
15        action = parse_action(thought)
16        if action.name == "finish":
17            return action.input
18
19        result = tools[action.name](**action.input)
20
21        # OBSERVE — feed the result back into the next thought
22        history.append({
23            "role": "tool",
24            "content": str(result)
25        })
26    raise RuntimeError("step budget exhausted")
Closing remark The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.
a · The THINK step

The model is asked to externalize its reasoning before any tool is touched. This thought becomes part of the history — visible, auditable, and available as context for the next decision.

b · The ACT step

parse_action extracts a structured tool call from the model's text. If the action is finish, the loop returns; otherwise the named tool runs with the parsed arguments.

c · The OBSERVE step

The tool's result is appended verbatim as a tool message — never summarized, never paraphrased. The next iteration of THINK sees exactly what the tool saw.
