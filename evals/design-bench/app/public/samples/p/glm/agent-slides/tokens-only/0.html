§ 1

The Loop

The ReAct loop is the simplest architecture that still counts as an agent: a controller that reasons about its next move, takes that move, and reads back what the world returns — then reasons again.

Three steps repeat until the question is answered. THINK selects an action and justifies it in natural language. ACT emits a structured tool call. OBSERVE injects the tool's return into context.

What makes this a controller and not a pipeline is the third step: OBSERVE does not terminate, it returns to THINK.

A Worked Trace

QUERY:"What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
01THOUGHTThe query hinges on two dates: the keynote and the trading day that follows. I need the keynote date first.
02ACTIONsearch("Jensen Huang 2024 keynote date")
03OBSERV."NVIDIA GTC 2024 keynote, March 18, 2024, San Jose."
04THOUGHTMarch 18 was a Monday. The closing price I want is for Tuesday, March 19, 2024 — the trading day after.
05ACTIONmarket.close("NVDA", "2024-03-19")
06OBSERV."NVDA close 2024-03-19: $117.59 (adjusted)."
07THOUGHTI have both anchors — keynote date and the following close — so the query is fully resolved.
08ACTIONanswer("$117.59, on 2024-03-19, the day after GTC.")
MARGIN ANNOTATIONS
STEP 01 · DECOMPOSITIONThe agent names its unknowns before reaching for a tool — this is the reasoning tax that buys interpretability.
STEP 04 · GROUNDING CHECKA calendar fact becomes a constraint on the next action; without it the date would be off by a weekend.
STEP 07 · TERMINATIONThe loop closes when the agent can state what it now knows, not when it runs out of steps.

§ 4 · WHERE LOOPS FAIL

§ 4

Where Loops Fail

Every iteration of the loop appends to the same context: the prior thought, the action, and the full return. By step twenty a modest agent has accumulated tens of thousands of tokens.

Models do not run out of capability in long loops — they run out of attention. The signal that mattered at step three is still in context, but the model has stopped reading it. This is the failure mode that no prompt template fixes.

§ 5 · THE LOOP, IN CODE
06 / 07
§ 5

The Loop, in Code

# minimal ReAct — twenty-five lines, no framework def react(question, tools, model, max_iter=12): ctx = system_prompt(question, tools) for step in range(max_iter): # THINK — reason about the next move thought, action = model.complete(ctx).parse() ctx.append({"role": "assistant", "content": thought}) if action.terminal: return action.answer # ACT — dispatch the chosen tool result = tools[action.name](**action.args) # OBSERVE — inject the return, loop resumes ctx.append({"role": "tool", "name": action.name, "content": str(result)}) raise LoopExhausted(step)
CLOSINGThe structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.
01
THINK STEPOne model call per iteration; the thought is parsed, not just emitted — the system reads its intent back.
02
ACT STEPTools are plain callables keyed by name. No schema, no plugin registry: the dispatch surface stays inspectable.
03
OBSERVE STEPThe return is re-injected under a tool role — the loop continues, context grows, attention thins.
