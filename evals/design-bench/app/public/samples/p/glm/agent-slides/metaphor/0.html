§ 1The Loop

The basic loop.

ReAct is the simplest controller you can build around a language model, and its simplicity is the point. The model emits a thought, takes an action against some environment — a search, a calculator, an API — and reads back the observation. That observation is appended to the working trace, and the cycle repeats. Nothing about the model changes between turns; what changes is the context the model reads on its next turn. The architecture is the cycle. The thing that makes it an agent rather than a chatbot is that the last step returns to the first.

Fig. 1The basic loop. Note that OBSERVE returns to THINK; this is what makes the architecture a controller, not a pipeline.

§ 2A Worked Trace

Six steps, one answer.

Query "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
01
Thought I need to find the date of Jensen Huang's 2024 keynote first, then look up NVDA's close on the trading day after.
Two unknowns in sequence — the date is a prerequisite, not a side-query.
02
Action search("Jensen Huang 2024 keynote date")
Tool call is parameterised — the action surface stays narrow.
03
Observation Keynote delivered January 8, 2024 at CES 2024 in Las Vegas.
Observation is appended, not interpreted — the model decides next.
04
Thought January 8 was a Monday. The next trading day is January 9, 2024. I need NVDA's close on that date.
A calendar inference the model performs itself — no tool needed.
05
Action price_lookup("NVDA", "2024-01-09")
Date is now grounded — the agent commits to a specific day.
06
Observation NVDA closed at $522.53 on 2024-01-09, up 0.9 % from prior close.
The observation carries enough to answer — no further inference.
07
Thought I have everything I need. The closing price on the trading day after the keynote was $522.53.
The trace closes with a synthesis step, not a tool call.

§ 4Where Loops Fail

The context window, against iteration.

An agent loop is, mechanically, an accumulator. Every turn the working trace grows: a thought here, a tool call there, a returned document of a few hundred tokens. Nothing is summarised, nothing is forgotten. Sooner or later the trace approaches the model's effective attention — the length at which it stops reading its own history faithfully. The loop does not break because the model is incapable; it breaks because the controller has accumulated more past than the model can hold in view. This is the dominant failure mode in production agents, and almost no architecture addresses it directly.

Fig. 3Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.

§ 5The Loop, in Code

A minimal ReAct loop.

1def react_loop(query, tools, max_iters=16):
2    trace = [{"role": "user", "content": query}]
3    for i in range(max_iters):
4        # ── THINK ──────────────────────────────
5        out = llm(trace, stop=["Action:"])
6        thought, action = parse(out)
7        trace.append({"role": "asst", "content": thought})
8        if action is None:
9            return thought            # final answer
10        # ── ACT ───────────────────────────────
11        name, args = action
12        result = tools[name](**args)
13        # ── OBSERVE ───────────────────────────
14        trace.append({
15            "role": "tool",
16            "content": str(result),
17        })
18    raise RuntimeError("context exhausted")
The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.
→THINK The model is stopped at "Action:" so the thought and the action are emitted in the same call but separable. The thought is the model's, not the system's.
→ACT The tool is dispatched by name with arguments the model produced. The environment — not the model — produces the result. The model never sees an effect it did not request.
→OBSERVE The observation is appended verbatim as a tool turn. Nothing is summarised; nothing is dropped. The next iteration's THINK reads the full trace.

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
