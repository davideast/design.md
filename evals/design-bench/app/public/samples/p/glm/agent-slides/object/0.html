§ 1 · The Loop
ii

The ReAct loop is the smallest interesting agent: a controller that alternates between thinking and acting, folding each observation back into its next thought. Nothing is pipelined; nothing runs forward only.

At each turn the model emits a thought, selects a tool, and receives an observation. The observation is appended to the trace, and the cycle repeats until the model judges it can answer.

The architecture's whole promise lives in that return stroke — the observation re-entering thought — because that is what makes the system a controller and not a pipeline.

§ 4 · Where Loops Fail
v

The dominant failure mode of agent loops is not the model's reasoning but its context. Every iteration appends a thought, an action, and an observation to the trace; tokens accumulate monotonically.

Somewhere past a dozen iterations the working set exceeds what the model effectively attends to. The agent begins to repeat itself, drop earlier constraints, or hallucinate tool outputs it never received — not because it cannot reason, but because the relevant state has fallen out of attention.

Most production agents fail somewhere in this region — not because the model is incapable, but because the context has become longer than the model's effective attention.

§ 5 · The Loop, in Code
vi
# A minimal ReAct loop, in 25 lines.

def react_loop(query, tools, model, max_steps=12):
    trace = [{"role": "user", "content": query}]
    for step in range(max_steps):

        # THINK
        thought = model.complete(trace, tools=tools)
        trace.append({"role": "assistant", "content": thought})

        # ACT
        if thought.finish:
            return thought.text
        action = parse_action(thought.text)
        result = tools[action.name].run(action.input)

        # OBSERVE
        trace.append({
            "role": "tool",
            "name": action.name,
            "content": result,
        })

    raise RuntimeError("context exhausted")
On the THINK step

The model emits a structured thought before any tool call — reasoning made visible on the trace.

On the ACT step

A parsed action selects a tool; the model never executes side-effects directly, only names them.

On the OBSERVE step

The tool's return is appended verbatim. Nothing is summarised; the loop trusts the trace.

The structure strictly interleaves reasoning and action. Forcing the model to externalize its thought before acting gives the system interpretability and reduces hallucinated state changes.

§ 6 · Ending
vii

The architecture is the loop. Everything else is a refinement of how the loop decides what to do next.
