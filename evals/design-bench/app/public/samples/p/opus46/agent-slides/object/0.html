Agent Architecture

How a language model becomes an actor: the perception–action loop, four canonical architectures, failure modes, and twenty-five lines of Python that implement the whole idea.

David East

14 Oct 2026

i
§ 1

The Loop

An agent is any system that perceives its environment through observations, selects an action via reasoning, executes that action, and folds the result back into the next cycle. This is the OODA loop stripped to its minimum: Think → Act → Observe. The model proposes; the tool disposes; the observation closes the loop. Every architecture in this handout is a variation on how many times the loop runs, who decides to stop, and what state persists between iterations.

A Worked Trace

User query: "What was NVDA's closing price last Friday?"

STEP 1  THINK
  I need to look up NVDA's stock price.
  I should call the market-data tool.

STEP 2  ACT
  get_stock_price(symbol="NVDA", date="last_friday")

STEP 3  OBSERVE
  → { close: 187.42, volume: 48_200_000 }

STEP 4  THINK
  I have the answer. Format for the user.
STEP 5  ACT
  Return final answer to user.

STEP 6  OBSERVE
  "NVDA closed at $187.42 last Friday
   on volume of 48.2 M shares."

STEP 7  THINK
  Task complete. Stop loop.

STEP 8  DONE
  ↩ yield answer

§ 4

Where Loops Fail

The loop degrades along two axes. First, context collapse: as the conversation grows, the model's effective attention narrows and it begins to repeat or contradict itself. Second, cost explosion: every iteration re-sends the full history, so token spend grows quadratically. Most production agents cap iterations and fall back to a planner when depth exceeds a threshold.

§ 5

The Loop, in Code

"""Minimal ReAct loop — 25 lines."""

def agent(query: str, tools: dict, model, max_iter=10):
    history = [{"role": "user", "content": query}]

    for i in range(max_iter):
        # ── THINK ──
        response = model.chat(history)

        if response.stop:
            return response.content          ← done

        # ── ACT ──
        name = response.tool_call.name
        args = response.tool_call.args
        result = tools[name](**args)

        # ── OBSERVE ──
        history.append({"role": "assistant",
                        "content": response.content})
        history.append({"role": "tool",
                        "name": name,
                        "content": str(result)})

    raise RuntimeError("max iterations")       ← bail

LINE 6 — the for-loop IS the agent.
Everything else is plumbing.

LINE 10 — the model decides when to stop; the loop merely obeys.

LINE 24 — without a cap the loop runs until the context window fills.
