Agent Architecture

How reasoning systems close the loop — from single-step reactions to multi-turn plans that remember, revise, and converge.

David East

§ 1

The Loop

Every agent architecture reduces to one primitive: a closed feedback loop. The model thinks, then acts, then observes the result of its action — and that observation becomes the input to the next thought. There is no beginning or end, only re-entry. The loop is not a metaphor; it is the literal control flow. ReAct, Reflexion, Plan-and-Execute — each is a variation on how many nodes sit inside the cycle and what state persists between turns.

A Worked Trace

Query: "What was NVDA's closing price last Friday?"

01 THINK I need the most recent Friday's date, then look up NVDA's close.
02 ACT get_date(relative="last friday") → 2026-10-09
03 OBSERVE {"date": "2026-10-09", "day": "Friday"}
04 THINK Good. Now call the stock API for NVDA on that date.
05 ACT stock_price(ticker="NVDA", date="2026-10-09")
06 OBSERVE {"close": 148.32, "currency": "USD"}
07 THINK I have the answer. Formulate a response to the user.
08 RESPOND NVDA closed at $148.32 USD on Friday 9 Oct 2026.

§ 4

Where Loops Fail

A loop without a termination condition is a liability. Token budgets grow linearly with each turn; the model may circle the same failing strategy indefinitely. The plot shows cumulative tokens across turns for three architectures. The steeper the slope, the more expensive the stall. Guardrails — max iterations, reflection gates, plan checkpoints — are not optional; they are the loop's brakes.

§ 5

The Loop, in Code

# The closed feedback loop in ~25 lines

from dataclasses import dataclass, field

@dataclass
class AgentState:
    messages: list = field(default_factory=list)
    max_turns: int = 10

def react_loop(state: AgentState, model, tools):
    """The loop: think → act → observe → repeat."""
    for turn in range(state.max_turns):
        # THINK
        response = model.generate(state.messages)

        if response.is_final:        # exit condition
            return response.content

        # ACT
        tool_name, tool_args = response.tool_call
        result = tools[tool_name](**tool_args)

        # OBSERVE  ← closes the loop
        state.messages.append({
            "role": "observation",
            "content": result,
        })
    raise RuntimeError("loop exceeded max turns")

Guardrail

max_turns bounds the cycle. Without it, runaway loops burn tokens and never converge.

Re-entry

The observation appended at the bottom feeds back to model.generate at the top — the literal closing arrow.

Exit

response.is_final is the only way out. The loop runs until the model decides it is done.
