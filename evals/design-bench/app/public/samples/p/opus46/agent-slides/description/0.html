Agent Architecture

How autonomous systems reason, act, and learn — a practical framework for understanding the architectures behind language-model agents.

David East 14 Oct 2026

§ 1. The Loop

At its core, every agent follows a single repeating pattern: think, then act, then observe the result. The model receives a context window — the task description, conversation history, and tool outputs — and produces a structured decision. That decision is executed against the environment, which returns new observations. These feed back into the context, and the cycle begins again. The loop terminates when the model emits a stop signal or a hard limit is reached. Everything else — planning, memory, retrieval — is elaboration on this fundamental triad.

§ 3. Four Architectures

Single Agent

One model, one loop. Direct tool access, minimal coordination overhead. Best for well-scoped tasks with clear termination.

Router / Dispatch

A classifier routes each request to a specialised sub-agent. No inter-agent communication. Fast, but brittle at boundaries.

Multi-Agent

Peer agents with shared memory collaborate through message passing. Powerful for complex workflows; coordination cost is non-trivial.

Hierarchical

An orchestrator decomposes goals into sub-tasks, delegating to child agents. Natural for planning-heavy domains; depth adds latency.

§ 4. Where Loops Fail

The agent loop is seductively general, but it breaks down in predictable ways. As iteration count grows, token expenditure grows super-linearly — each step re-processes the entire context. Beyond roughly fifteen iterations, most loops either degrade in quality, hallucinate observations, or enter repetitive cycles. The practical ceiling is not compute but coherence: the model's ability to maintain a consistent plan degrades with context length.

§ 5. The Loop, in Code

from typing import Any from dataclasses import dataclass, field @dataclass class AgentState: messages: list[dict] = field(default_factory=list) done: bool = False def agent_loop( state: AgentState, model: Any, tools: dict, max_iter: int = 15, ) -> AgentState: """Core agent loop: think → act → observe.""" for _ in range(max_iter): # THINK: model decides next action response = model.generate(state.messages) if response.stop: state.done = True break # ACT: execute the chosen tool result = tools[response.tool](response.args) # OBSERVE: feed result back in state.messages.append(result.to_message()) return state
① State

The conversation history is the agent's only persistent memory. Each loop iteration appends to it.

② Guard rail

max_iter=15 prevents runaway loops. In practice, most tasks resolve within 5–8 iterations.

③ Feedback

Tool results are serialised back into the message stream, closing the loop.

"The loop is simple. The craft is knowing when to stop."
