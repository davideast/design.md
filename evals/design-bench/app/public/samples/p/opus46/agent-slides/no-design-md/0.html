Agent Architecture

On loops, traces, and the structures by which language models act.
Dr. Anika Patel · Distributed Systems Lab, ETH Zürich 14 October 2026
§ 1

The Loop

A ReAct agent interleaves reasoning with action in a tight cycle. At each step the model first thinks—producing a chain-of-thought trace that decomposes the problem, identifies unknowns, and proposes a next move. It then acts, invoking an external tool or API. The environment returns an observation, which the model reads before thinking again. Because the observation feeds back into the next thought, the system forms a closed control loop rather than a feed-forward pipeline. Termination occurs when the model emits a final-answer action.

A Worked Trace

Query: "What was the closing price of NVDA the day after Jensen Huang's 2024 keynote?"
THOUGHT₁ I need to find the date of Jensen Huang's 2024 keynote first.
decompose the query
ACTION₁ search("Jensen Huang 2024 keynote date")
tool invocation
OBSERVATION₁ GTC keynote delivered on 18 March 2024.
grounding fact received
THOUGHT₂ The day after is 19 March 2024. I need the NVDA closing price on that date.
date arithmetic
ACTION₂ stock_price("NVDA", date="2024-03-19", field="close")
structured API call
OBSERVATION₂ NVDA closed at $878.37 on 19 March 2024.
numeric result
THOUGHT₃ I now have the answer. I should verify this is the correct trading day (not a weekend).
self-verification step
ACTION₃ finish("The closing price of NVDA on 19 March 2024 was $878.37.")
terminal action

§ 4

Where Loops Fail

Every iteration of the loop appends new tokens—thought, action call, and observation—to an ever-growing context window. Early iterations are cheap, but cost compounds: each new step must attend to the full history. Beyond roughly fifteen iterations the context saturates, responses degrade, and the model either hallucinates an answer or enters a repetitive loop. Mitigation strategies include summarisation checkpoints, sliding-window truncation, and hierarchical memory, but none eliminate the fundamental pressure.

§ 5

The Loop, in Code

from llm import complete from tools import dispatch def react_loop(query: str, max_steps: int = 20): history = [f"Query: {query}"] for step in range(max_steps): # ── THINK ── prompt = "\n".join(history) thought = complete(prompt, stop=["ACTION:"]) history.append(f"THOUGHT: {thought}") # ── ACT ── action = complete( "\n".join(history), stop=["OBSERVATION:"] ) if action.startswith("FINISH:"): return action.removeprefix("FINISH: ") history.append(f"ACTION: {action}") # ── OBSERVE ── observation = dispatch(action) history.append(f"OBSERVATION: {observation}") raise RuntimeError("Max steps exceeded")

"Interleaving reasoning and action in twenty-five lines — the rest is engineering."

Think

The model generates a chain-of-thought trace given the full history. This is the reasoning step — no side effects.

Act

The model emits a structured action string. A "FINISH:" prefix is the sentinel for termination; otherwise, the action is dispatched to a tool.

Observe

The tool returns an observation string, appended to history. The loop now returns to THINK with fresh evidence.
