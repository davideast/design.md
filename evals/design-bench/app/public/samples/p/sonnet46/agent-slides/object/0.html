§ 1

The Loop


Every capable agent reduces to a single iterative pattern: perceive, reason, act, and observe consequences. The model generates a thought — an internal monologue framing the problem — selects an action from a vocabulary of tools, executes it against the world, and incorporates the resulting observation into its context window. This loop continues until a terminal condition is met: an answer is produced, a budget is exhausted, or the model determines no further steps are needed. Simple in structure. Profound in consequence.

A Worked Trace

Query: "What was NVDA's closing price on 2024-01-15?"
THOUGHT 1 I need NVDA's closing price for a specific date. I'll query the financial data API.
ACTION 1 get_stock_price(ticker="NVDA", date="2024-01-15")
OBSERVATION 1 Error: Market closed on 2024-01-15 (Martin Luther King Jr. Day).
THOUGHT 2 The market was closed. I need to find the last open trading day before Jan 15.
ACTION 2 get_trading_calendar(from="2024-01-12", to="2024-01-15")
OBSERVATION 2 Trading days: [2024-01-12]. Last open: Friday, January 12.
ACTION 3 get_stock_price(ticker="NVDA", date="2024-01-12")
OBSERVATION 3 NVDA closed at $547.10 on 2024-01-12. Note: requested date was a holiday.
Thought articulates need before any API call.
Error is informative; the agent recovers gracefully.
Calendar context enables correct date repair.
Answer includes explicit date caveat.

Four Architectures

REACT

Interleaves reasoning traces with actions. Thought precedes every tool call — the minimal composition.

REFLEXION

Adds verbal self-evaluation after failure. Agent critiques its trace, accumulates reflections across episodes.

PLAN-AND-EXECUTE

Separates planning from execution. Planner decomposes the task; executor works through each step with tool use.

TREE-OF-THOUGHTS

Explores branching solution paths. A search heuristic (beam / MCTS) prunes and selects the most promising branch.

04
§ 4

Where Loops Fail

Iterative loops carry a hidden cost: every step consumes tokens. Performance degrades not linearly, but at an inflection point — the agent appears functional until, suddenly, it is not. Context overflow corrupts earlier reasoning; the model loses track of its plan. Understanding the failure regime requires measuring both axes simultaneously.

The Loop, in Code

def react_loop(query: str, tools: dict, max_steps: int = 10) -> str:
    history = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": query},
    ]

    for step in range(max_steps):          # budget guard
        response = llm.complete(history)
        thought, action = parse(response)

        if action.is_final():              # terminal check
            return action.value

        tool_fn = tools[action.name]
        observation = tool_fn(**action.args)

        history.extend([                    # grow context
            {"role": "assistant", "content": response},
            {"role": "user",
             "content": f"Observation: {observation}"},
        ])

    raise RuntimeError("Max steps exceeded")

The loop is twenty lines. The difficulty is in everything that surrounds it.

L 7

max_steps is a hard budget — the only guaranteed termination condition.

L 11

The model decides when it is done. is_final() detects a special terminal action token.

L 17

History grows monotonically. No forgetting — until the context window is full.
