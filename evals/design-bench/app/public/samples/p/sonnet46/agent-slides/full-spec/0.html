§ 1

The Loop

Every capable agent reduces to a single iterative pattern: perceive, reason, act, observe consequences. The model generates a thought — an internal monologue framing the problem — selects an action from a vocabulary of tools, executes it against the world, and incorporates the resulting observation into its context window. This loop continues until a terminal condition is met: an answer is produced, a budget is exhausted, or the model determines no further steps are needed. Simple in structure; profound in consequence.

A Worked Trace

Query: "What was NVDA's closing price on 2024-01-15?"
THOUGHT 1I need NVDA's closing price for that date. I'll query the financial data API.
ACTION 1get_stock_price(ticker="NVDA", date="2024-01-15")
OBSERVATION 1Error: Market closed on 2024-01-15 (Martin Luther King Jr. Day).
THOUGHT 2The market was closed that day. I need to find the last open trading day before Jan 15.
ACTION 2get_trading_calendar(from="2024-01-12", to="2024-01-15")
OBSERVATION 2Trading days in range: [2024-01-12]. Last open: Friday, January 12.
ACTION 3get_stock_price(ticker="NVDA", date="2024-01-12")
OBSERVATION 3NVDA closed at $547.10 on 2024-01-12. Requested date was a holiday.
Thought articulates the plan before any tool call.
Error is informative; recovery is graceful, not a failure.
Calendar context supplies the information needed for repair.
The final answer grounds itself with an explicit date caveat.

§ 3

Four Architectures

REACT

Interleaves reasoning traces with action calls in a single pass. Thought precedes every tool invocation — the simplest composition of language and tool use.

REFLEXION

Adds verbal self-evaluation after failure. The model composes a critique of its own trace before retrying, accumulating reflections across episodes.

PLAN-AND-EXECUTE

Decouples planning from execution. An upstream planner decomposes the goal; a downstream executor iterates through each step with tool use.

TREE-OF-THOUGHTS

Explores a tree of partial solutions. A search policy — beam search or MCTS — prunes and selects the most promising branch for elaboration.

04
§ 4

Where Loops
Fail

Iterative loops carry a hidden cost: every step consumes tokens. Performance degrades not linearly, but at an inflection point — the agent appears functional until, quite suddenly, it is not. Context overflow corrupts earlier reasoning; the model loses track of its own plan. Each new observation silently displaces older information. Understanding the failure regime requires measuring both axes simultaneously.

The Loop, in Code

def react_loop(query: str, tools: dict, max_steps: int = 10) -> str:
    history = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": query},
    ]

    for step in range(max_steps):          # budget guard
        response = llm.complete(history)
        thought, action = parse(response)

        if action.is_final():              # terminal check
            return action.value

        tool_fn = tools[action.name]
        observation = tool_fn(**action.args)

        history.extend([                    # grow context
            {"role": "assistant", "content": response},
            {"role": "user",
             "content": f"Observation: {observation}"},
        ])

    raise RuntimeError("Max steps exceeded")

The loop is twenty lines. The difficulty is in everything that surrounds it.

L 7

max_steps is a hard budget — the only guaranteed termination condition.

L 11

The model decides when it is done. is_final() detects a terminal action token.

L 17

History grows monotonically. No forgetting — until the context window is full.
