§ 1

The Loop

Every capable agent reduces to a single iterative pattern: perceive, reason, act, and observe consequences. The model generates a thought — an internal monologue framing the problem — selects an action from a vocabulary of tools, executes it against the world, and incorporates the resulting observation into its context window. This continues until a terminal condition is met: an answer is produced, a budget is exhausted, or the model determines no further steps are needed. Simple in structure, profound in consequence.

§ 2

A Worked Trace

Query: "What was NVDA's closing price on 2024-01-15?"
THOUGHT 1 I need to look up NVDA's closing price for that specific date. I will query the financial data API.
ACTION 1 get_stock_price(ticker="NVDA", date="2024-01-15")
OBSERVATION 1 Error: Market closed on 2024-01-15 (Martin Luther King Jr. Day).
THOUGHT 2 The market was closed. I should determine the last open trading day before the 15th.
ACTION 2 get_trading_calendar(from="2024-01-12", to="2024-01-15")
OBSERVATION 2 Trading days in range: [2024-01-12]. Last open: Friday, January 12.
ACTION 3 get_stock_price(ticker="NVDA", date="2024-01-12")
OBSERVATION 3 NVDA closed at $547.10 on 2024-01-12. Requested date was a market holiday.
The thought articulates a plan before any tool is called.
A meaningful error enables graceful recovery — not failure.
Calendar query provides the context needed for repair.
Answer is grounded with explicit date caveat.

§ 3

Four Architectures

REACT

Interleaves reasoning traces with action calls in a single pass. Each thought precedes its action — the simplest composition of language and tool use.

REFLEXION

Adds verbal self-evaluation after trajectory failure. The agent composes a linguistic critique before retrying, accumulating reflections across episodes.

PLAN-AND-EXECUTE

Decouples planning from execution. An upstream planner decomposes the task; a separate executor iterates through each step, enabling parallelism and replanning.

TREE-OF-THOUGHTS

Explores a tree of partial solutions. A search policy — beam search or MCTS — prunes branches and selects the most promising path for further elaboration.

04 — 07
§ 4

Where Loops
Fail

Iterative loops carry a hidden cost: every step consumes tokens. Performance degrades not linearly, but at an inflection point — the agent appears functional until, suddenly, it is not. Context overflow corrupts earlier reasoning; the model loses its plan. Each new observation silently displaces older information. Understanding the failure regime requires measuring both axes simultaneously.

§ 5

The Loop, in Code

def react_loop(query: str, tools: dict, max_steps: int = 10) -> str:
    history = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": query},
    ]

    for step in range(max_steps):          # budget guard
        response = llm.complete(history)
        thought, action = parse(response)

        if action.is_final():              # terminal check
            return action.value

        tool_fn = tools[action.name]
        observation = tool_fn(**action.args)

        history.extend([                    # grow context
            {"role": "assistant", "content": response},
            {"role": "user",
             "content": f"Observation: {observation}"},
        ])

    raise RuntimeError("Max steps exceeded")

The loop is twenty lines. The difficulty lies in everything that surrounds it.

line 7

max_steps is a hard budget — the only guaranteed termination condition.

line 11

The model decides when it is done. is_final() detects a special terminal action.

line 17

History grows monotonically. No forgetting — until the window is full.
