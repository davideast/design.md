§ 1

The Loop

Every capable agent, regardless of architecture, reduces to a single iterative pattern: perceive, reason, act, and observe the consequences. The model generates a thought — an internal monologue that frames the problem — selects an action from a vocabulary of tools, executes it against the world, and incorporates the resulting observation into its context window. This loop continues until a terminal condition is met: an answer is produced, a budget is exhausted, or the model determines no further steps are needed. Simple in structure, profound in consequence.

A Worked Trace

Query: "What was NVDA's closing price on 2024-01-15?"

THOUGHT 1 I need to look up NVDA's closing price for a specific date. I'll use the financial data API.
ACTION 1 get_stock_price(ticker="NVDA", date="2024-01-15")
OBSERVE 1 Error: Market was closed on 2024-01-15 (Martin Luther King Jr. Day).
THOUGHT 2 The market was closed. I should find the last trading day before 2024-01-15.
ACTION 2 get_trading_calendar(from="2024-01-12", to="2024-01-15")
OBSERVE 2 Trading days: [2024-01-12]. Last open day was Friday, January 12th.
ACTION 3 get_stock_price(ticker="NVDA", date="2024-01-12")
OBSERVE 3 NVDA closed at $547.10 on 2024-01-12. Note: market closed on requested date.
Model identifies tool need before calling it.
Error is informative — handled gracefully.
Recovery: agent queries for calendar context.
Final answer grounds with caveat about the date.

§ 3

Four Architectures

ReAct

Interleaves reasoning traces with action calls in a single pass. Thought precedes every action.

Reflexion

Adds a verbal self-reflection step. After failure, the model critiques its own trace before retry.

Plan-and-Execute

Separates planning from execution. A planner produces a task list; an executor works through each step.

Tree-of-Thoughts

Explores branching reasoning paths. A search heuristic selects the most promising partial solution.

§ 4

Where Loops Fail

Iterative loops carry a hidden cost: every step consumes tokens. Performance degrades not at first, but at an inflection point — the agent appears functional until, quite suddenly, it is not. Context overflow corrupts earlier reasoning; the model loses track of its own plan. Iteration count compounds this: each new observation reshapes the context, and older information is silently displaced. Understanding the failure regime requires measuring both axes simultaneously.

The Loop, in Code

def react_loop(query: str, tools: dict, max_steps: int = 10) -> str: history = [ {"role": "system", "content": SYSTEM_PROMPT}, {"role": "user", "content": query}, ] for step in range(max_steps): # budget guard response = llm.complete(history) thought, action = parse(response) if action.is_final(): # terminal check return action.value tool_fn = tools[action.name] observation = tool_fn(**action.args) history.extend([ # grow context {"role": "assistant", "content": response}, {"role": "user", "content": f"Observation: {observation}"}, ]) raise RuntimeError("Max steps exceeded")

The loop is twenty lines. The difficulty is in what surrounds it.

line 7 max_steps is a hard budget — the only guaranteed termination condition.
line 11 The model decides when it is done. is_final() checks for a special action token.
line 18 History grows monotonically. No forgetting — until the context window is full.
