§ 1

The Loop

Every capable agent reduces to a single iterative pattern: perceive, reason, act, and observe consequences. The model generates a thought — an internal monologue framing the problem — selects an action from a vocabulary of tools, executes it against the world, and incorporates the resulting observation into its context window. This loop continues until a terminal condition is met: an answer is produced, a budget is exhausted, or the model determines no further steps are needed. Simple in structure, profound in consequence.

A Worked Trace

Query: "What was NVDA's closing price on 2024-01-15?"

THOUGHT 1 I need to look up NVDA's closing price. I'll query the financial data API for that date.
ACTION 1 get_stock_price(ticker="NVDA", date="2024-01-15")
OBSERVATION 1 Error: Market was closed on 2024-01-15 (Martin Luther King Jr. Day).
THOUGHT 2 The market was closed that day. I should find the last open trading day before Jan 15.
ACTION 2 get_trading_calendar(from="2024-01-12", to="2024-01-15")
OBSERVATION 2 Trading days in range: [2024-01-12]. Last open day: Friday, Jan 12.
ACTION 3 get_stock_price(ticker="NVDA", date="2024-01-12")
OBSERVATION 3 NVDA closed at $547.10 on 2024-01-12. Note: requested date was a holiday.
Thought precedes every action call.
Errors are informative — handled gracefully by recovery.
Calendar query provides necessary context for repair.
Final answer includes provenance caveat.

§ 3

Four Architectures

REACT

Interleaves reasoning traces with action calls. Thought precedes every tool invocation.

REFLEXION

Adds verbal self-reflection after failure. The model critiques its trace and retries with improved strategy.

PLAN-AND-EXECUTE

Separates planning from execution. A planner produces a step list; an executor works through each item.

TREE-OF-THOUGHTS

Explores branching reasoning paths. A search heuristic selects the most promising partial solution to continue.

04
§ 4

Where Loops Fail

Iterative loops carry a hidden cost: every step consumes tokens. Performance degrades not at first but at an inflection point — the agent appears functional until, quite suddenly, it is not. Context overflow corrupts earlier reasoning. Each observation reshapes the window, silently displacing older information. Understanding the failure regime requires measuring both axes simultaneously.

The Loop, in Code

def react_loop(query: str, tools: dict, max_steps: int = 10) -> str:
    history = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": query},
    ]

    for step in range(max_steps):          # budget guard
        response = llm.complete(history)
        thought, action = parse(response)

        if action.is_final():              # terminal check
            return action.value

        tool_fn = tools[action.name]
        observation = tool_fn(**action.args)

        history.extend([                    # grow context
            {"role": "assistant", "content": response},
            {"role": "user",
             "content": f"Observation: {observation}"},
        ])

    raise RuntimeError("Max steps exceeded")

The loop is twenty lines. The difficulty is in everything that surrounds it.

L 7

max_steps is a hard budget — the only guaranteed termination.

L 11

The model decides when it is done. is_final() checks for a special action token.

L 17

History grows monotonically. No forgetting — until the context window fills.
